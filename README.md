# 都市の鼓動 (City Pulse)

千代田区の実データだけで作った、**タスクのない鑑賞用3Dビジュアライザー**です。
24時間分の鉄道・バスの実際の時刻表通りの動きを光の軌跡として描き、
実況の天気(降水・暑さ指数)を大気の演出に重ね、時間帯ごとに空と街の色調が
移り変わる中で、都市が呼吸するように混み合ったり静まったりする様子を
「鼓動」として鑑賞する作品です。

操作は **視点移動(ドラッグ/回転/ズーム)** と **鼓動チャートのクリック/ドラッグによる
時間帯の移動** の2つだけ。ルート検索や避難所案内のような実用タスクは一切ありません。

姉妹プロジェクトの「[モグルート](../claude_opendata/shelter_route)」(避難所ルート検索アプリ)で
検証済みの deck.gl + MapLibre + 実GTFSデータの技術基盤を流用し、全く別のコンセプトの
作品として作り直しました。

## 他の都市でつくる(ホーム画面)

トップページ(ホーム画面)から、**GTFSのzipをアップロードするだけで、日本のほかの都市でも同じ表現で作れます**。

- 処理はすべてブラウザ内(Web Worker)で行い、GTFSはサーバーへ送信されません。作成した都市はその端末のブラウザ内(IndexedDB)にだけ保存されます。
- **JR東日本を既定で重ねる**: 公共交通オープンデータチャレンジで提供されているJR東日本のGTFSを、サーバー側で取得し、作成した街の範囲内の運行だけを加工して自動で重ねます(ホーム画面のチェックで外せます)。範囲にJRが無ければ何も足しません。
  - チャレンジ限定ライセンス(第8条4項)により、JRのGTFSそのものや復元できる加工データを公開・再配布してはいけないため、**zipは配布せず、サーバーのメモリ上にだけ保持**します(`jreast.py`)。**リポジトリにもJR由来のデータは含めません**(`data/anim_cache/jreast_*` は `.gitignore` 対象)。
  - **東京サンプルのJRも同じ方式**です。`data/transit_pulse.json` は都営のみで、JR東日本は表示時にサーバーが取得して重ねます(サーバー起動直後は準備に1〜2分かかり、その間は都営のみを表示します。トークン未設定ならJRなしで表示します)。手元だけで試す場合は `python pipeline/build_pulse_data.py --with-jr` でJR入りのデータを作れますが、出力を公開してはいけません。
  - **街の範囲・カメラの表示範囲は、JR以外のGTFSだけ**で決めます(JRは範囲内の運行を重ねるだけ)。JRのzipを手動で読み込んだ場合(事業者名にJRを含むもの)も同じ扱いです。JR以外のGTFSが1つも無いときだけ、JRで範囲を決めます。
  - **JRは、範囲内で運行本数の多い都道府県だけを表示します**。国土地理院の逆ジオコーダで停留所の都道府県を判定し、範囲内で最も運行の多い都道府県に対して25%以上ある都道府県を残します(例: 東京の範囲では東京都だけ、横浜の範囲では神奈川県と東京都)。
  - **表示するJRが通る場所には、建物・メッシュも必ず出します**。メッシュにはJRの停留所も加え、OSMの建物は、範囲全体を絞り込んでいる場合でもJRが通る場所(停留所の周囲)はすべての建物を取得します。
  - サーバーに環境変数 `ODPT_CHALLENGE_TOKEN`(チャレンジ用アクセストークン)を設定してください。未設定なら、JRの重ね合わせは自動的に無効になり、ほかの機能は通常どおり動きます。ローカルでは `pipeline/.odpt_token` からも読みます。
  - 許諾は2027年3月12日までです。終了後はデータを削除してください。
- 複数のGTFS: zipは最大8個まで同時に読み込めます(例: 鉄道会社+バス会社)。各GTFSから便を取り出して1つの街に重ねます。対象エリアは全GTFSの停留所をまとめて決め、運行日はGTFSごとに選びます。
- 運行: GTFSから代表的な平日ダイヤ1日分を選び、停留所が最も集まる範囲(最大約24km四方)を自動で切り出します。
- 鉄道/バスの区分: 既定はGTFSの路線種別(route_type)による自動判定です。3・11・200番台・700〜800番台を「バス」、それ以外(鉄道・地下鉄・路面電車・モノレール・ケーブルカー・フェリーなど)を「鉄道」に数えます。種別が正しく入っていないGTFSは、ファイルごとに「すべて鉄道/すべてバスとして扱う」を指定できます。
- 建物: 次の順で自動選択します。光り方(接触・周辺・拠点ほど明るくなる蓄積)は全都市共通です。
  1. **PLATEAU** — 3D Tilesのみの提供で1タイルが約13MBと重く、ブラウザ内で扱えないため対象外にしました。
  2. **OpenStreetMap**(Overpass API) — 範囲内の建物数に応じて「すべて → 中層以上 → 高層以上 → 超高層」と自動で絞り込みます(上限約9万棟)。建物が多すぎる都市は、範囲全体を「タグ付きの建物」、中心部を「すべての建物」で重ねて取得します。
     - Overpass APIが混雑・停止していて繋がらない場合や建物が足りない場合は、同じOSM由来の **ベクトルタイル(OpenFreeMap・OpenMapTiles形式)** から建物と高さ(render_height)を取得します。中心に近いタイルは細かい建物まで、離れるほど高い建物中心に絞ります。
     - 一部の区画だけ取れない場合は、取得できた分で作成を続けます。
  3. **メッシュ** — OSMの建物がほとんど無い地域(またはOSMを取得できなかった場合)は、GTFSの運行頻度から作る250m地域メッシュ(緯度7.5秒×経度11.25秒)を立ち上げて代替します。保存情報に理由が残り、ホーム画面の「OSMの建物で作り直す」でGTFSを再アップロードせずに取り直せます。
- 建物データのクレジット: © OpenStreetMap contributors(ODbL)。ベクトルタイルは [OpenFreeMap](https://openfreemap.org) / © OpenMapTiles。
- 天気の熱気エフェクトは東京(サンプル)のみです。
- 検証: 東京(JR東日本の広域フィード)・横浜(相模鉄道)・架空の離島路線(メッシュ代替)・鉄道+バスの複数GTFS(種別の誤記を指定で補正)で動作確認済みです。

## 見どころ

- **鼓動チャート**: 画面下部のEKG(心電図)風チャートは、5分刻みで「その瞬間に
  走行中の便数」を集計した実データのヒストグラム。ラッシュ時に脈が高鳴り、
  深夜にフラットラインへ近づく様子がそのまま「都市の鼓動」になっています。
  クリック/ドラッグで好きな時間帯へジャンプできます。
- **稼働率に連動する光の軌跡**: 走行中の便数が多い時間帯ほど、軌跡の色が
  明るく鮮やかになり、逆に少ない時間帯は1本1本の軌跡が長く尾を引く
  ("光跡写真"のような表現)よう、`TripsLayer` の色とtrailLengthを
  リアルタイムの稼働率に応じて連続的に変化させています。
- **時間帯で移ろう空と街の色**: 深夜の藍色、夜明けの橙、日中の青空、夕暮れの
  茜色へと、建物のトーンと画面全体の色被り(`skyFx`)が滑らかに移り変わります。
- **実況の暑さ指数を大気に重ねる**: 環境省の暑さ指数(WBGT)実況値を1分おきに
  取得し、危険な暑さ指数であれば橙色の熱気エフェクトを画面に重ねます。これは
  シミュレーション時間(24時間ループ)とは独立した「今、現実の空の下で
  見ている」というレイヤーです。
- **自動再生・自動回転**: 何も操作しなければ24時間が実時間5分でループ再生され、
  カメラもゆっくり自動回転します。操作すると数秒間は自動回転が止まり、
  視点操作に専念できます。

## データソース(すべて無料。JR東日本のみアクセストークンが必要)

| データ | 出典 | 用途 |
|---|---|---|
| 建物形状・高さ | OpenStreetMap (Overpass API) | 3D押し出しビル |
| 都営地下鉄・都営バス時刻表(GTFS) | [公共交通オープンデータセンター (ODPT)](https://ckan.odpt.org/dataset) | 24時間分の実運行アニメーション(キー不要) |
| JR東日本 時刻表(GTFS) | ODPT [公共交通オープンデータチャレンジ2026](https://ckan.odpt.org/organization/jreast) 限定データセット | 中央線・山手線など主要線区の運行アニメーション。**リポジトリには含めず**、サーバーがトークンで取得して表示時に重ねる(要 `ODPT_CHALLENGE_TOKEN`) |
| 降水ナウキャスト | 気象庁 高解像度降水ナウキャスト(タイル) | 雨天時の大気演出(現在は非表示設定) |
| 暑さ指数(WBGT) | 環境省 熱中症予防情報サイト API | 熱気エフェクト |

GTFSキャッシュ(`data/anim_cache/`内の都営分)は、姉妹プロジェクト「モグルート」で
構築したものと同じデータを再利用しています。建物データは東京23区全域を
Overpass APIから取得したものです(`pipeline/fetch_buildings.py`)。23区全棟
(100万棟超)は描画負荷が大きすぎるため、中高層以上(`building:levels>=5`
または`height>=10m`相当)のみに絞り込み約9.3万棟に抑えています。鉄道・バスの
軌跡データは千代田区周辺のみが対象のため、郊外の建物の上を軌跡が通ることは
ありません。

## 構成

```
CityPulse/
├── server.py                     # 薄いFastAPIサーバー(静的配信+天気プロキシのみ)
├── web/
│   └── index.html                # deck.gl + MapLibre による3Dビジュアライザー本体
├── pipeline/
│   ├── build_pulse_data.py       # 24時間分の運行データ+鼓動ヒストグラムを生成
│   ├── fetch_jreast.py           # (手元だけで試す用・要トークン) JR東日本GTFSをanim_cacheへ取得。出力は公開しない
│   ├── fetch_buildings.py        # Overpass APIから対象エリアの建物3D形状を取得
│   └── .odpt_token                # ODPTアクセストークン(gitignore対象・各自で用意)
└── data/
    ├── buildings_3d.json         # 建物の3D形状(23区全域・中高層以上、約9.3万棟)
    ├── anim_cache/                # GTFS全日程キャッシュ
    │   ├── bus_stop_times.parquet / bus_meta.json      # 都営バス(モグルートから再利用)
    │   ├── rail_stop_times.parquet / rail_meta.json    # 都営地下鉄(モグルートから再利用)
    └── transit_pulse.json        # build_pulse_data.py の出力(約21,600便分)
```

ルーティング計算・避難所データ・DBは一切なく、静的データ配信+天気APIプロキシ
だけのシンプルな構成です。

## セットアップ・起動

```bash
# 1. (任意・初回のみ) 対象エリアを変える場合、建物データを再取得
python pipeline/fetch_buildings.py

# 2. JR東日本は、リポジトリには含めず、サーバーがトークンで取得します。
#    ローカルで動かす場合は、developer.odpt.org で発行した「公共交通オープンデータ
#    チャレンジ2026」のアクセストークンを pipeline/.odpt_token に保存する
#    (本番は環境変数 ODPT_CHALLENGE_TOKEN)。fetch_jreast.py は手元で試す用です。

# 3. (初回のみ) 24時間分の運行データを生成
python pipeline/build_pulse_data.py

# 4. サーバー起動
python server.py
# → http://127.0.0.1:8600 を開く
```

必要なPythonパッケージ: `fastapi`, `uvicorn`, `requests`, `pillow`, `pandas`, `pyarrow`

## 実装メモ / 既知の制約

- **降水強度の推定は近似値です。** 気象庁は降水ナウキャストタイルの正式な
  RGB配色表を公開していないため、一般に知られる配色傾向(弱=青→強=赤紫)を
  もとにした色相分類で推定しています(`server.py` の `_classify_precip_pixel`)。
  参考値として扱ってください。
- **バスは全便の30%をサンプリング表示**しています(1日あたり実便数は約4万便あり、
  全件描画するとペイロードが大きくなりすぎるため)。鉄道は間引いていません。
- deck.glの既知の落とし穴を2つ、モグルート開発時の知見から先回りして回避しています:
  `TripsLayer`・`ScatterplotLayer` への `parameters: { depthTest: false }`
  (押し出しビルに軌跡が隠れてしまう問題)と、TextLayerを使う場合の日本語
  `characterSet` 明示(本作品はラベル表示を持たないため直接は該当しませんが、
  今後ラベルを追加する場合は要注意)。
